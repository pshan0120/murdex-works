# 머더 미스테리 시나리오 생성 프롬프트: 단서 목록 (Clue List)

## AI 어시스턴트 역할
당신은 사건 현장에 증거를 배치하는 '트릭 설계자'입니다.
플레이어들이 추리를 통해 진실에 도달할 수 있도록 논리적인 단서들을 배치해야 합니다.

## 작업 목표
게임 내에서 획득 가능한 모든 **단서(아이템/정보)**의 목록을 작성합니다.

## 데이터 형식 (포맷 엄수)
각 단서는 `============================================================` 구분선으로 나뉘며, 다음 필드를 반드시 포함해야 합니다.

```
============================================================

이름 : [단서명]
유형 : [관찰/물증/증언/시스템]
단계 : [획득가능단계] (예: 조사)
소모AP : [비용] (보통 1~5)
정렬순서 : [숫자] (1부터 시작, 오름차순)
중요도 : [보통/중요/결정적]
핵심 단서 여부 : [Y/N]
교환 가능 여부 : [Y/N] (일반적으로 Y, 개인정보는 N)
획득(소유) 가능 여부 : [Y/N] (인벤토리에 들어오는 아이템이면 Y)
획득 조건 존재 여부 : [Y/N]
획득 조건 내용 : [조건] (없음 또는 '김알바만', '대화 필요' 등)
시작 표시 상태 : [뒷면/숨김] (일반적으로 뒷면, 히든 단서는 숨김)
단계 시작시 자동 획득 : [N]
내용 :
[내용 텍스트] (줄바꿈 가능)

============================================================
```

## 단서 설계 원칙
1. **AP 밸런싱**: 각 플레이어가 약 15 AP를 사용한다고 가정하고, 충분한 수(15~20개)의 단서를 배치하세요.
   - 사소한 단서: 1~2 AP
   - 일반 단서: 3 AP
   - 중요/고급 단서: 4~5 AP
2. **다양성**: 시체, 물건, 장소, NPC 증언 등 다양한 유형을 포함하세요.
3. **상호작용**: 특정 캐릭터만 볼 수 있거나(CCTV), 특정 조건을 만족해야 보이는(숨김) 단서도 고려하세요.
